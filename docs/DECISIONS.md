# Implementation decisions

- Use the existing project root for the section 19 layout; avoid a redundant nested clearline directory.
- Use SQLite only for isolated unit tests; Docker, demos and integration checks use PostgreSQL 16 and pgvector.
- Keep the configured embedding default local; explicitly select hash for offline demo/CI to avoid downloading a model.
- Demo credentials are public, local-only configuration; both services bind to loopback.
- Preserve excess EFT money as unapplied_cents in a resolved case; never overdraw an invoice even for an overpayment decision.
- Use a fictional beneficiary suffix of 0042; the sender's stored account suffix is not evidence of the business's beneficiary account.
- Keep historical bank observations separate from the 400 evaluation cases and authorize their synthetic ledger entries with rules-match audit events.
- Run evaluations in disposable PostgreSQL schemas; use SQLite only for hermetic unit evaluation tests.
- Do not estimate live model pricing; report SDK token usage and leave unknown API cost unpriced.
- Serve the UI through nginx with a same-origin API proxy; avoid browser CORS configuration and ship no remote fonts or assets.
- Use host API port 18000 to avoid an existing service on 8000; the container API remains on 8000.
- Add a bounded read-only /invoices endpoint for human correction choices; derive labels and outstanding balances from the database.
- Serialize reconciliation, reviews, imports and proof verification with one PostgreSQL transaction advisory lock; favor auditable consistency over throughput for this single-workspace demo.
- Require a human note to approve a proposal with conflicting proof evidence; corrections already require an explanation.
- Test live clients against recorded HTTP responses through their actual SDKs; keep paid provider evaluations opt-in and unreported until measured.
- Use the MCP SDK v1 API with an explicit <2 dependency cap; avoid adopting a different major-version interface during this build.
- Require the PostgreSQL agent identity and read-only transactions for MCP; tool hints alone do not enforce permissions.
- Reuse validated agent queries for MCP; bank-specific evidence requires an explicit bank-line identifier.
- Keep clean-checkout smoke validation in an isolated Compose project and fresh volumes; preserve the active review workspace.
- Browser opening is best-effort on supported desktop systems; headless users always receive the demo URL.
- Redact MCP SDK validation errors at the public tool-dispatch boundary; third-party error messages can echo sensitive arguments even when successful results are masked.

- Apply the user-supplied Apple design system to the app shell; reserve CSS Liquid Glass for navigation and keep financial content opaque.
- Make the sample a separate, disposable in-memory adapter; never use it as an implicit fallback for a disconnected API.
- Use explicit `/sample` and `/workspace` URL namespaces with React Router 7; selected proposals, tabs and filters are addressable and support browser history.
- Poll committed API state instead of introducing a message broker or pretending to stream an agent transaction; expose pause, refresh and stale/offline states.
- Add a bounded masked audit-summary endpoint for the live panel; exclude full tool payloads and retain the existing full per-proposal audit path.
- Restore saved appearance before React mounts; avoid transitions from a light first frame when the saved theme is dark.
- Keep initial review selection in local state rather than a data-load redirect; a delayed queue response must not override a navigation click.
- Allow submitted mutations to finish after leaving review, while guarding page-local navigation and feedback against unmount.
- Keep the standard backdrop-filter declaration after the prefixed fallback; verify the optimized production stylesheet in a real browser to catch CSS optimizer regressions.
- Place the scroll-edge scrim outside the filtered toolbar; soften the top gap without sampling through a filtered ancestor or intercepting navigation.
- Define the HTTP/sample request contract in the API module; workspace infrastructure must not depend on a type owned by sample fixtures.
- Treat notification lifetime as message-owned; unrelated parent renders cannot restart dismissal, and cancelled invoice lookups cannot replace current choices.
- Expose CSV preparation through a write-free authenticated preview endpoint; share validation with the eventual atomic import so preview cannot weaken server-side checks.
- Treat preview as a schema check, not a promise that current database identities are conflict-free; revalidate and roll back the whole import on conflict.
- Record import counts and file fingerprints inside the import transaction; keep filenames and rejected CSV values out of error/audit summaries.
- Publish evaluation evidence as a validated generated asset; keep Sample offline and distinguish historical published results from current connected-workspace metrics.
- Recompute release gates and key ratios when exporting report evidence; retain explicit null slots for unrun providers and hash the original source files for provenance.
- Use ordinary links for URL-driven retrieval choices; avoid transient radio state during router transitions and retain native browser history behavior.
- Commit HTTP database transactions before sending success; use function-scoped dependencies so commit-time failures cannot produce a successful acknowledgement.
- Require explicit finite bounded release measurements and an observed completion count; never infer operational success from a missing metric.
- Treat empty MCP search results as valid protocol responses; verify both an empty database and seeded records in CI.
- Pin workflow actions to resolved commits, grant read-only repository permissions, and retain failed-run diagnostics for seven days.
- Model CSV import stages as a discriminated union in a dedicated controller; keep file identity, preview and confirmation together instead of synchronizing independent state flags.
- Guard submissions before React's next render; cancel only preview reads and let acknowledged writes refresh workspace state after navigation.
